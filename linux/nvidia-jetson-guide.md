# Οδηγός NVIDIA Jetson Το

Chloros
στο NVIDIA Jetson επιτρέπει την επεξεργασία πολυφασματικών εικόνων στην «άκρη» — στο πεδίο, σε UAV και σε απομακρυσμένες εγκαταστάσεις. Το Chloros
1.3.0 αναγνωρίζει το μοντέλο Jetson κατά την εκκίνηση και βελτιστοποιεί τη στρατηγική επεξεργασίας του ανάλογα με το υλικό που εντοπίζει. **Δεν απαιτείται χειροκίνητη ρύθμιση.**
{% hint style="info" %}
**Το πακέτο Jetson 1.3.0 εκτελείται στην GPU του Jetson.** Το `chloros_1.3.0_arm64_jp6.deb` έχει δημιουργηθεί για το JetPack 6 και χρησιμοποιεί την έκδοση του PyTorch για CUDA του JetPack 6, οπότε η επεξεργασία — συμπεριλαμβανομένου του Texture Aware debayer — εκτελείται στην GPU του Orin. Το πακέτο δεν περιλαμβάνει το CUDA: χρησιμοποιεί τις βιβλιοθήκες CUDA και cuDNN που εγκαθιστά το JetPack 6 (το `sudo apt install nvidia-jetpack` σε μια εικόνα που δεν τις διαθέτει). Όπου δεν είναι διαθέσιμη GPU με CUDA, η επεξεργασία εκτελείται στην CPU και το Texture Aware χρησιμοποιεί το Standard debayer.
{% endhint %}

## Υποστηριζόμενα μοντέλα Jetson

| Μοντέλο                | RAM            | Στρατηγική επεξεργασίας                                     | Συνιστώμενη χρήση                                          |
| -------------------- | -------------- | ------------------------------------------------------- | -------------------------------------------------------- |
| **Jetson AGX Orin**  | 32-64 GB κοινόχρηστη | `GPU_PARALLEL` (2 workers)                              | Μέγιστη απόδοση, μεγάλα σύνολα δεδομένων                      |
| **Jetson Orin NX**   | 8-16 GB κοινόχρηστη  | `GPU_PARALLEL` (2 εργαζόμενοι, 16 GB) / `GPU_SINGLE` (8 GB)   | Κύρια σύσταση για ανάπτυξη στο πεδίο              |
| **Jetson Orin Nano** | 8 GB κοινόχρηστη μνήμη     | `GPU_SINGLE` (1 εργαζόμενος, διαδοχική επεξεργασία)                     | Υπολογιστική ισχύς περιφερειακού επιπέδου                                 |

{% hint style="info" %}
Το πακέτο Linux
arm64 απαιτεί το **JetPack 6**, το οποίο είναι διαθέσιμο στην οικογένεια Jetson Orin. Τα παλαιότερα μοντέλα (Nano, TX2, Xavier NX) δεν μπορούν να εκτελέσουν το JetPack 6 και δεν υποστηρίζονται από το τρέχον πακέτο.
{% endhint %}

## Απαιτήσεις

* **JetPack 6.x** (συνιστάται η πιο πρόσφατη έκδοση)
* **NVIDIA CUDA και cuDNN** από το JetPack 6 (`sudo apt install nvidia-jetpack` αν η εικόνα σας δεν τα περιλαμβάνει)
* **Πρόγραμμα Chloros
+ επί πληρωμή** — Επίπεδο Copper ή υψηλότερο (απαιτείται για κάθε πρόσβαση σε CLI
/SDK
· επιβάλλεται από την πλευρά του διακομιστή)

## Εγκατάσταση

```bash
# Install the arm64 .deb package (JetPack 6) -- apt, not dpkg -i, so the
# Python SDK's requirements (python3-numpy, python3-requests) come too
sudo apt install ./chloros_1.3.0_arm64_jp6.deb

# Verify installation
chloros-cli --version    # prints "Chloros CLI 1.3.0"
python3 -c "import chloros_sdk; print(chloros_sdk.__version__)"   # the .deb installs the SDK

# Run system diagnostics
chloros-cli selftest
```

Το `.deb` εγκαθιστά το SDK
της Python
για το σύστημα `python3`, που αντιστοιχεί σε αυτή την έκδοση. Μόνο ένα virtualenv χρειάζεται να εγκατασταθεί σε αυτό το πακέτο wheel: `pip install /usr/lib/chloros/sdk/chloros_sdk-*.whl` (εντελώς εκτός σύνδεσης). Για γενικές λεπτομέρειες εγκατάστασης σε Linux
, τοποθεσίες αρχείων και αντιμετώπιση προβλημάτων, ανατρέξτε στην [Εγκατάσταση σε Linux
](linux-installation.md).

{% hint style="info" %}
**Δεν απαιτείται πλέον αποσυμπίεση κατά την εκκίνηση.** Από την έκδοση 1.3.0 και μετά, το backend και η CLI
εγκαθίστανται χωρίς αποσυμπίεση στον κατάλογο `/usr/lib/chloros/`, οπότε δεν αποσυμπιέζονται πλέον σε έναν προσωρινό κατάλογο κάθε φορά που εκκινούν. Τα προσωρινά αρχεία εξακολουθούν να αποθηκεύονται αυτόματα στο `/mnt/ssd/tmp`, εφόσον υπάρχει αυτός ο φάκελος· διαφορετικά, μπορείτε να ορίσετε το `TMPDIR` σε μια διαδρομή στο NVMe σας (`export TMPDIR=/mnt/nvme/tmp`).
{% endhint %}

## Δυναμική προσαρμογή υπολογιστικής ισχύος στο Jetson

### Πώς λειτουργεί

Κατά την εκκίνηση, το Chloros
δημιουργεί προφίλ του συστήματός σας:

1. **Ανιχνεύει το μοντέλο Jetson** μέσω του `/proc/device-tree/model`
2. **Διαβάζει τη διαθέσιμη κοινόχρηστη μνήμη GPU/CPU** (το Jetson χρησιμοποιεί ενοποιημένη μνήμη)
3. **Ρωτά το PyTorch αν μπορεί να χρησιμοποιήσει CUDA** — με το CUDA και το cuDNN του JetPack 6 εγκατεστημένα, μπορεί
4. **Επιλέγει αυτόματα μια στρατηγική επεξεργασίας** (`GPU_PARALLEL`, `GPU_SINGLE` ή `CPU_PARALLEL`) και τον αριθμό των worker

Η απόφαση εξαρτάται από τη **συνολική κοινόχρηστη μνήμη RAM**, όχι από το όνομα του μοντέλου:

* **Με συνολική μνήμη RAM κάτω των 12 GB**(όλα τα Jetson 8 GB):**1 worker — σκόπιμη διαδοχική επεξεργασία**. Η μνήμη είναι πολύ περιορισμένη για ταυτόχρονους workers, οπότε οι εικόνες επεξεργάζονται μία κάθε φορά. Στα Jetson με**8 GB ή λιγότερο**, το Thread 3 παρακάμπτει εντελώς την ομάδα εργαζομένων και εκτελεί την εργασία ανά εικόνα ενδοδιαδικαστικά. Το αρχείο καταγραφής του backend ονομάζει αυτή τη στρατηγική `GPU_SINGLE`.
* **12 GB ή περισσότερα**(Orin NX 16 GB, AGX Orin): η ενοποιημένη μνήμη πληροί τις προϋποθέσεις για το `GPU_PARALLEL`, αλλά ο αριθμός των εργαζομένων**περιορίζεται σε 2 στα Jetson** — η GPU, η μνήμη RAM των διεργασιών εργαζομένων και τα περιβάλλοντα CUDA ανά εργαζόμενο αντλούν όλα από την ίδια κοινόχρηστη ομάδα, οπότε περισσότεροι εργαζόμενοι ενέχουν τον κίνδυνο σφαλμάτων εξάντλησης μνήμης.
* **Χωρίς χρησιμοποιήσιμο CUDA** (λείπουν οι βιβλιοθήκες CUDA του JetPack): `CPU_PARALLEL` στα 12 GB ή περισσότερα, μία εικόνα κάθε φορά παρακάτω.

Μπορείτε να παρακάμψετε την αυτόματη επιλογή με τη μεταβλητή περιβάλλοντος `CHLOROS_STRATEGY` — δείτε [Δυναμική Προσαρμογή Υπολογιστικής Ικανότητας](../processing-architecture/dynamic-compute-adaptation.md#manual-strategy-override).

### Συμπεριφορά ανά μοντέλο

| Μοντέλο Jetson                | Στρατηγική       | Εργαζόμενοι | Εκτέλεση                                      |
| --------------------------- | -------------- | ------- | ---------------------------------------------- |
| **Jetson Orin Nano 8 GB**    | `GPU_SINGLE`   | 1       | Διαδοχικός βρόχος εντός διεργασίας (`tiled_gpu` υπό πίεση μνήμης) |
| **Jetson Orin NX 8GB**      | `GPU_SINGLE`   | 1       | Διαδοχικός βρόχος εντός της διεργασίας                     |
| **Jetson Orin NX 16GB**     | `GPU_PARALLEL` | 2       | Ταυτόχρονες διεργασίες-εργάτες, διαδρομή `fused_gpu`  |
| **Jetson AGX Orin 32-64GB** | `GPU_PARALLEL` | 2       | Ταυτόχρονες διεργασίες εργασίας, διαδρομή `fused_gpu`  |

Η βασική διαφορά μεταξύ των πλατφορμών είναι η **μνήμη**. Ένα Jetson 8 GB πρέπει να επεξεργάζεται τις εικόνες μία κάθε φορά, χρησιμοποιώντας μια προσέγγιση με τμηματοποίηση που εξοικονομεί μνήμη όταν η πίεση είναι υψηλή, ενώ ένα Orin 16 GB+ μπορεί να επεξεργάζεται 2 εικόνες ταυτόχρονα μέσω της GPU, χρησιμοποιώντας τον συνδυασμένο αγωγό υψηλότερης απόδοσης.

### Προϋπολογισμός GPU ανά μοντέλο

Κάθε μοντέλο Jetson διαθέτει επίσης ένα προφίλ υλικού που ορίζει το μέγιστο ποσό μνήμης που μπορεί να διεκδικήσει η επεξεργασία από την κοινόχρηστη δεξαμενή και κλιμακώνει τα μεγέθη παρτίδων:

| Μοντέλο | Ανώτατο όριο προϋπολογισμού GPU | Πολλαπλασιαστής μεγέθους παρτίδας | Διατηρείται για το σύστημα/την οθόνη |
| --- | --- | --- | --- |
| **Jetson Orin Nano** | 70% | ×0,8 | 2,0 GB |
| **Jetson Orin NX** | 75% | ×1,0 | 3,0 GB |
| **Jetson AGX Orin** | 80% | ×1,5 | 4,0 GB |

Η ανιχνευόμενη μνήμη RAM προσαρμόζει το προφίλ: σε ένα Jetson που αναφέρει **16 GB ή περισσότερα**, ο πολλαπλασιαστής παρτίδας αυξάνεται κατά ×1,2. Το βασικό μέγεθος παρτίδας πριν από τους πολλαπλασιαστές είναι 8 εικόνες.

Για την πλήρη αναφορά σχετικά με την προσαρμογή υπολογιστικής ισχύος, ανατρέξτε στο [Dynamic Compute Adaptation](../processing-architecture/dynamic-compute-adaptation.md).

## Όριο συχνότητας GPU για το Texture Aware στα μοντέλα Nano και Orin Nano

Το Texture Aware debayer εκτελεί συμπερασμό νευρωνικού δικτύου μέσω της GPU, κάτι που μπορεί να προκαλέσει **προειδοποιήσεις υπερφόρτωσης ρεύματος**σε μοντέλα Jetson χαμηλής κατανάλωσης (κατηγορίας 10-15 W) όταν η GPU λειτουργεί σε πλήρη ταχύτητα ρολογιού. Όταν περάσετε το `--debayer texture-aware` σε ένα**Jetson Nano ή Orin Nano**, το CLI
ελέγχει τη μέγιστη συχνότητα της GPU και την περιορίζει στα **510 MHz** (510000000) εάν αυτή είναι επί του παρόντος υψηλότερη:

* Εάν το CLI
μπορεί να εγγράψει στον κόμβο sysfs της συχνότητας της GPU, το όριο **εφαρμόζεται αυτόματα** και εμφανίζεται ένα μήνυμα επιβεβαίωσης.
* Εάν όχι (απαιτείται δικαιώματα root), το CLI
εμφανίζει την ακριβή εντολή `sudo` για να εφαρμόσετε το όριο χειροκίνητα, περιμένει λίγο ώστε να προλάβετε να τη διαβάσετε και στη συνέχεια συνεχίζει — η επεξεργασία συνεχίζεται, αλλά ενδέχεται να εμφανιστούν προειδοποιήσεις υπερφόρτωσης ρεύματος.

Για να εφαρμόσετε το όριο μόνοι σας πριν από την επεξεργασία:

```bash
echo 510000000 | sudo tee /sys/devices/platform/bus@0/17000000.gpu/devfreq/17000000.gpu/max_freq
```

Τα μοντέλα υψηλότερης ισχύος (Orin NX 25W, AGX Orin 60W) λειτουργούν στην πλήρη ταχύτητα της GPU· δεν εφαρμόζεται όριο. Το Standard debayer δεν ενεργοποιεί ποτέ το όριο σε κανένα μοντέλο.

{% hint style="info" %}
**Το Texture Aware στο Jetson εκτελεί πάντα μία εικόνα κάθε φορά.** Κάθε worker θα χρειαζόταν το δικό του περιβάλλον CUDA (~1 GB) καθώς και το δικό του αντίγραφο του μοντέλου αποθορυβοποίησης, κάτι που η ενοποιημένη μνήμη δεν μπορεί να υποστηρίξει — επομένως, στο Jetson η διαδρομή του Texture Aware είναι καρφωμένη σε έναν μόνο worker με σειριοποιημένη πρόσβαση στην GPU. Αναμένεται το Texture Aware να είναι αισθητά πιο αργό από το Standard σε οποιοδήποτε Jetson. Το Texture Aware εφαρμόζεται σε εικόνες του Survey3
: οι καταγραφές του LATTICE λαμβάνουν πάντα το Standard debayer. Χωρίς μια χρησιμοποιήσιμη GPU CUDA, η εκτέλεση χρησιμοποιεί το Standard, και το backend καταγράφει μια γραμμή `[DEBAYER] … needs a CUDA GPU …` που εξηγεί τον λόγο (όπως φαίνεται με το `chloros-cli --verbose`).
{% endhint %}

## Διαχείριση θερμοκρασίας

Οι συσκευές Jetson έχουν περιορισμένο θερμικό περιθώριο, ειδικά σε κλειστές εγκαταστάσεις ή σε εφαρμογές αερομεταφερόμενες. Το Chloros
παρακολουθεί τη θερμοκρασία του SoC και περιορίζει αυτόματα το μέγεθος των παρτίδων:

| Θερμοκρασία         | Ενέργεια                                            |
| ------------------- | ------------------------------------------------- |
| **&lt; 70°C**          | Κανονική λειτουργία — πλήρης ταχύτητα επεξεργασίας          |
| **70°C** (Προειδοποίηση) | Το μέγεθος της παρτίδας μειώνεται προοδευτικά (100% → 50% μεταξύ 70°C και 80°C) |
| **80°C** (Κρίσιμη) | Εντατική μείωση της ταχύτητας (50% → 0% μεταξύ 80°C και 90°C) |
| **90°C** (Τερματισμός λειτουργίας) | Πλήρης διακοπή της επεξεργασίας της GPU — απαιτείται ψύξη |

{% hint style="warning" %}
**Εξασφαλίστε επαρκή αερισμό και απαγωγή θερμότητας** για συνεχή επεξεργασία, ειδικά σε κλειστά περιβλήματα πεδίου ή αερομεταφερόμενα συστήματα. Ο θερμικός περιορισμός θα μειώσει την απόδοση επεξεργασίας για την προστασία του υλικού.
{% endhint %}

## Διαχείριση μνήμης

Οι συσκευές Jetson χρησιμοποιούν **ενιαία μνήμη** — η GPU και η CPU μοιράζονται την ίδια φυσική μνήμη RAM. Η αναφερόμενη VRAM (π.χ. ~15,3 GB σε ένα Orin NX 16 GB) δεν είναι αποκλειστική μνήμη GPU· είναι η ίδια μνήμη RAM που χρησιμοποιούν το λειτουργικό σύστημα και κάθε άλλη διεργασία.

### Προειδοποίηση και συστάσεις σχετικά με την ανταλλαγή

Πριν από την επεξεργασία στο Jetson, η CLI
μετρά τις εικόνες RAW στον φάκελο εισόδου σας (`.tif`, `.tiff`, `.raw`, `.dng` — οι προεπισκοπήσεις JPG δεν υπολογίζονται), εκτιμά τη μέγιστη μνήμη που απαιτεί η εκτέλεση και **προειδοποιεί πριν από την έναρξη** εάν η μνήμη RAM + η μνήμη ανταλλαγής είναι πιθανό να μην επαρκούν. Η προειδοποίηση έχει τίτλο `LOW MEMORY WARNING - Jetson Detected`, εμφανίζει τον αριθμό των εικόνων σας, τη μνήμη RAM, το τρέχον swap και την εκτιμώμενη μέγιστη χρήση, και στη συνέχεια δίνει τις ακριβείς εντολές `fallocate` / `chmod` / `mkswap` / `swapon` προσαρμοσμένες στο μέγεθος το έργο σας (ποτέ μικρότερο από 8 GB). Κάνει παύση λίγων δευτερολέπτων ώστε το μήνυμα να μην χαθεί στην κύλιση προς τα πίσω, και στη συνέχεια η επεξεργασία συνεχίζεται.**Εκτιμήσεις μνήμης που χρησιμοποιούνται από την προειδοποίηση:**

| Λειτουργία Debayer | Βάση | Ανά εικόνα |
| --- | --- | --- |
| Τυπική | ~1,5 GB | ~10 MB |
| Με αναγνώριση υφής | ~2,5 GB (μοντέλο + περιβάλλον εκτέλεσης Python) | ~15 MB |

Η προειδοποίηση ενεργοποιείται όταν η εκτιμώμενη μέγιστη τιμή υπερβαίνει τη μνήμη RAM + swap μείον ένα περιθώριο ασφαλείας 1 GB, και υπολογίζει μόνο το swap **που υποστηρίζεται από αρχεία** — μια ρύθμιση που χρησιμοποιεί αποκλειστικά zram θα εξακολουθεί να επισημαίνεται.

Για να προσθέσετε swap χειροκίνητα (παράδειγμα: 8 GB):

```bash
# Check current memory and swap
free -h

# Create a swap file
sudo fallocate -l 8G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile

# Make persistent across reboots
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
```

### Διαχείριση OOM (Out of Memory)

Κατά τη διάρκεια της επεξεργασίας, το Chloros
παρακολουθεί τη μνήμη της GPU και μειώνει ομαλά την απόδοση αντί να διακοπεί η λειτουργία:

1. Όταν η χρήση της μνήμης της GPU υπερβαίνει το **85%**, τα μεγέθη των παρτίδων μειώνονται προληπτικά
2. Εάν εξακολουθεί να συμβαίνει συμβάν εξάντλησης μνήμης, το μέγεθος της παρτίδας **μειώνεται στο μισό** και μειώνεται ξανά στο μισό σε κάθε διαδοχικό OOM· κάθε επόμενη επιτυχημένη παρτίδα αναστρέφει αυτή την ποινή κατά ένα βήμα
3. Υπό συνεχή πίεση, ο αγωγός επιστρέφει από το `fused_gpu` στη διαδρομή `tiled_gpu`, η οποία είναι πιο αποδοτική ως προς τη μνήμη, και, ως έσχατη λύση, στην επεξεργασία μέσω της CPU

Επειδή η GPU μοιράζεται τη μνήμη RAM του Jetson, η μνήμη RAM σε συνδυασμό με το swap εξακολουθεί να περιορίζει την εκτέλεση — η παραπάνω προειδοποίηση για το swap αποτελεί τον έλεγχο που πρέπει να λαμβάνεται υπόψη.

## Εγκατάσταση στο πεδίο

### Παράγοντες που αφορούν την κατανάλωση ισχύος

| Μοντέλο Jetson     | Τυπική κατανάλωση ισχύος | Σημειώσεις                   |
| ---------------- | ------------------ | ----------------------- |
| Jetson Orin Nano | 7-15W              | Υποδοχή DC τύπου «barrel»          |
| Jetson Orin NX   | 10-25W             | Υποδοχή DC τύπου «barrel»          |
| Jetson AGX Orin  | 15-60W             | USB-C PD ή υποδοχή τύπου «barrel» |

Προγραμματίστε τον προϋπολογισμό ισχύος σας για συνεχή επεξεργασία — η μέγιστη κατανάλωση ισχύος παρατηρείται κατά τη διάρκεια του Thread 3 (Επεξεργασία), το οποίο απαιτεί εντατική χρήση της GPU.

### Συστάσεις αποθήκευσης

* **SSD NVMe** συνιστάται έντονα για εγκαταστάσεις arm64
* Οι κάρτες SD είναι πολύ αργές για επεξεργασία — χρησιμοποιήστε τις μόνο ως μέσο εκκίνησης
* Προβλέψτε 2-3 φορές το μέγεθος των ακατέργαστων δεδομένων εικόνας για τα επεξεργασμένα αποτελέσματα

### Λειτουργία χωρίς οθόνη μέσω SSH Το

Chloros
του SSH
είναι ιδανικό για εγκαταστάσεις Jetson χωρίς οθόνη:

```bash
# SSH into the Jetson
ssh user@jetson-hostname

# Process a dataset
chloros-cli process /data/datasets/flight001 --format "TIFF (32-bit, Percent)"

# Monitor export progress
chloros-cli export-status
```

### Backend συνεχούς λειτουργίας για συγχρονισμό χρόνου LATTICE / DAQ-E

Εάν το Jetson σας ελέγχει κάμερες LATTICE ή αισθητήρες φωτός DAQ-E χωρίς οθόνη, ενεργοποιήστε την υπηρεσία systemd του backend **ως χρήστης σας**, ώστε ο grandmaster PTP να λειτουργεί συνεχώς και τα σενάρια του SDK
να εντοπίζουν ένα backend σε λειτουργία (η μονάδα είναι εγκατεστημένη αλλά δεν είναι ενεργοποιημένη από προεπιλογή):

```bash
sudo systemctl enable --now chloros-backend@$USER.service    # $USER expands to your user name
chloros-cli time-sync status
```

Στη συνέχεια, το backend λειτουργεί ως εσείς: οι καταγραφές που αποθηκεύει είναι δικές σας και χρησιμοποιεί το `chloros-cli login` σας. Δείτε την [Εγκατάσταση σε Linux
](linux-installation.md#always-on-ptp-for-headless-hosts) για λεπτομέρειες, συμπεριλαμβανομένου του root `chloros-backend.service` και του τρόπου με τον οποίο το πακέτο καθιστά τις θύρες PTP 319/320 δεσμεύσιμες χωρίς δικαιώματα root.

### Αυτοματοποιημένη επεξεργασία με το systemd

Δημιουργήστε μια υπηρεσία systemd για αυτοματοποιημένη επεξεργασία:

```ini
# /etc/systemd/system/chloros-process.service
[Unit]
Description=Chloros Automated Processing
After=network.target

[Service]
Type=oneshot
User=chloros
ExecStart=/usr/bin/chloros-cli process /data/incoming --output /data/processed
StandardOutput=append:/var/log/chloros-process.log
StandardError=append:/var/log/chloros-process.log

[Install]
WantedBy=multi-user.target
```

Το `chloros-cli process` τερματίζεται με μη μηδενικό αποτέλεσμα όταν μια εκτέλεση που ζήτησε προϊόντα δεν εγγράφει εικόνες, οπότε η κατάσταση αποτυχίας του systemd είναι σημαντική για την παρακολούθηση.

Συνδυάστε το με ένα χρονόμετρο του systemd για προγραμματισμένη επεξεργασία:

```ini
# /etc/systemd/system/chloros-process.timer
[Unit]
Description=Run Chloros Processing Every Hour

[Timer]
OnCalendar=hourly
Persistent=true

[Install]
WantedBy=timers.target
```

```bash
sudo systemctl enable chloros-process.timer
sudo systemctl start chloros-process.timer
```

## Παραδείγματα ροών εργασίας

### Βασική επεξεργασία στο Jetson

```bash
#!/bin/bash
# Process a drone flight dataset on Jetson
chloros-cli process /data/flights/flight_042 \
    --output /data/processed/flight_042 \
    --format "TIFF (32-bit, Percent)" \
    --indices NDVI GNDVI OSAVI
```

### PythonSDK
στο Jetson

```python
from chloros_sdk import ChlorosLocal

with ChlorosLocal() as chloros:
    chloros.create_project("field_survey_042")
    chloros.import_images("/data/flights/flight_042")
    chloros.configure(
        indices=["NDVI", "GNDVI", "OSAVI"],
        export_format="TIFF (32-bit, Percent)",
        reflectance_calibration=True
    )
    chloros.process(mode="parallel")

print("Processing complete!")
```

### Μαζική επεξεργασία πολλαπλών πτήσεων

```bash
#!/bin/bash
# Process all flight datasets in a directory
for flight in /data/flights/*/; do
    name=$(basename "$flight")
    echo "Processing $name..."
    chloros-cli process "$flight" \
        --output "/data/processed/$name" \
        --format "TIFF (32-bit, Percent)" \
        --indices NDVI OSAVI
    echo "Completed $name"
done
```

## Συστήματα Jetson που συνιστώνται για χρήση στο πεδίο

Για εφαρμογές στο πεδίο και σε αεροσκάφη, εξετάστε τις παρακάτω επιλογές πλακέτας βάσης Jetson Orin NX 16GB:

* **Αεροσκάφη/δρόνοι**: Συστήματα με αντοχή σε κραδασμούς (MIL-STD), ελαφριά (κάτω από 300 g), παθητική ψύξη
* **Ανθεκτική χρήση στο πεδίο**: Αδιάβροχα περιβλήματα IP67/IP69K με δυνατότητα σύνδεσης κάμερας PoE GigE
* **Ελάχιστες απαιτήσεις/οικονομική επιλογή**: Κιτ προγραμματιστών με πρόσθετα περιβλήματα

Επικοινωνήστε με την [Υποστήριξη MAPIR
](https://www.mapir.camera/community/contact) για συγκεκριμένες προτάσεις υλικού ανάλογα με το σενάριο εγκατάστασής σας.
