# Οδηγός NVIDIA Jetson Το

Chloros

στο NVIDIA Jetson επιτρέπει την επεξεργασία πολυφασματικών εικόνων στην «άκρη» — στο πεδίο, σε UAV και σε απομακρυσμένες εγκαταστάσεις. ΤοChloros

1.2.0 αναγνωρίζει το μοντέλο Jetson κατά την εκκίνηση και βελτιστοποιεί τη στρατηγική επεξεργασίας ανάλογα με το υλικό που εντοπίζει. **Δεν απαιτείται χειροκίνητη ρύθμιση.**

## Δυναμική προσαρμογή υπολογιστικής ισχύος στο Jetson

### Πώς λειτουργεί

Κατά την εκκίνηση, τοChloros

δημιουργεί προφίλ του συστήματός σας:

1. **Ανιχνεύει το μοντέλο Jetson** μέσω του `/proc/device-tree/model`
2. **Διαβάζει τη διαθέσιμη κοινόχρηστη μνήμη GPU/CPU** (το Jetson χρησιμοποιεί ενοποιημένη μνήμη)
3. **Επιλέγει μια στρατηγική επεξεργασίας** (`GPU_PARALLEL`, `GPU_SINGLE` ή `CPU_PARALLEL`)
4. **Ορίζει τον αριθμό των εργαζομένων, τον τύπο του αγωγού και την κατανομή μνήμης** αυτόματα

Η απόφαση βασίζεται στη **συνολική κοινόχρηστη μνήμη RAM**, όχι στο όνομα του μοντέλου:

* **Με συνολική μνήμη RAM κάτω των 12 GB**(όλα τα Jetson 8 GB): `GPU_SINGLE` με**1 εργαζόμενο — σκόπιμη διαδοχική επεξεργασία**. Η μνήμη είναι πολύ περιορισμένη για ταυτόχρονους εργαζόμενους, οπότε οι εικόνες επεξεργάζονται μία κάθε φορά. Στα Jetson με**8 GB ή λιγότερο**, το Νήμα 3 παρακάμπτει εντελώς την ομάδα εργαζομένων και εκτελεί την εργασία ανά εικόνα ενδοδιαδικαστικά.
* **12 GB ή περισσότερο**(Orin NX 16 GB, AGX Orin): η ενοποιημένη μνήμη πληροί τις προϋποθέσεις για το `GPU_PARALLEL`, αλλά ο αριθμός των worker**περιορίζεται σε 2 στα Jetson** — η GPU, η μνήμη RAM των διεργασιών εργαζομένων και τα περιβάλλοντα CUDA ανά εργαζόμενο αντλούν όλα από την ίδια κοινόχρηστη ομάδα, οπότε περισσότεροι εργαζόμενοι ενέχουν κίνδυνο σφαλμάτων εξάντλησης μνήμης.

Μπορείτε να παρακάμψετε την αυτόματη επιλογή με τη μεταβλητή περιβάλλοντος `CHLOROS_STRATEGY` — δείτε [Δυναμική Προσαρμογή Υπολογιστικής Ισχύος](../processing-architecture/dynamic-compute-adaptation.md#manual-strategy-override).

### Συμπεριφορά ανά μοντέλο

| Μοντέλο Jetson                | Στρατηγική       | Εργαζόμενοι | Εκτέλεση                                      |
| --------------------------- | -------------- | ------- | ---------------------------------------------- |
| **Jetson Orin Nano 8GB**    | `GPU_SINGLE`   | 1       | Διαδοχικός βρόχος εντός διεργασίας (`tiled_gpu` υπό πίεση μνήμης) |
| **Jetson Orin NX 8GB**      | `GPU_SINGLE`   | 1       | Διαδοχικός βρόχος εντός διεργασίας                     |
| **Jetson Orin NX 16GB**     | `GPU_PARALLEL` | 2       | Ταυτόχρονες διεργασίες εργασίας, διαδρομή `fused_gpu`  |
| **Jetson AGX Orin 32-64GB** | `GPU_PARALLEL` | 2       | Ταυτόχρονες διεργασίες εργασίας, διαδρομή `fused_gpu`  |

Η βασική διαφορά μεταξύ των πλατφορμών είναι η **μνήμη**. Ένα Jetson 8 GB πρέπει να επεξεργάζεται τις εικόνες μία κάθε φορά, χρησιμοποιώντας μια προσέγγιση με τμηματοποίηση (tiled) που εξοικονομεί μνήμη όταν η πίεση είναι υψηλή, ενώ ένα Orin 16 GB+ μπορεί να εκτελεί 2 εικόνες ταυτόχρονα μέσω της GPU, χρησιμοποιώντας τον συνδυασμένο αγωγό (fused pipeline) υψηλότερης απόδοσης.

### Προϋπολογισμός GPU ανά μοντέλο

Κάθε μοντέλο Jetson διαθέτει επίσης ένα προφίλ υλικού που ορίζει το μέγιστο ποσό που μπορεί να διεκδικήσει η επεξεργασία από την κοινόχρηστη μνήμη και κλιμακώνει τα μεγέθη παρτίδων:

| Μοντέλο | Ανώτατο όριο προϋπολογισμού GPU | Πολλαπλασιαστής μεγέθους παρτίδας | Διατηρείται για το σύστημα/την οθόνη |
| --- | --- | --- | --- |
| **Jetson Orin Nano** | 70% | ×0,8 | 2,0 GB |
| **Jetson Orin NX** | 75% | ×1,0 | 3,0 GB |
| **Jetson AGX Orin** | 80% | ×1,5 | 4,0 GB |

Η ανιχνευόμενη μνήμη RAM προσαρμόζει το προφίλ: σε ένα Jetson που αναφέρει **16 GB ή περισσότερα**, ο πολλαπλασιαστής παρτίδας αυξάνεται κατά ×1,2. Το βασικό μέγεθος παρτίδας πριν από τους πολλαπλασιαστές είναι 8 εικόνες.

Για την πλήρη αναφορά προσαρμογής υπολογιστικής ισχύος, ανατρέξτε στο [Dynamic Compute Adaptation](../processing-architecture/dynamic-compute-adaptation.md).

## Όριο συχνότητας GPU για το Texture Aware στα Nano και Orin Nano

Το Texture Aware debayer εκτελεί συμπερασμό νευρωνικού δικτύου μέσω της GPU, κάτι που μπορεί να προκαλέσει **προειδοποιήσεις υπερφόρτωσης ρεύματος**σε μοντέλα Jetson χαμηλής κατανάλωσης (κατηγορίας 10-15 W) όταν η GPU λειτουργεί σε πλήρη ταχύτητα ρολογιού. Πριν από την επεξεργασία με το «Texture Aware» σε**Jetson Nano ή Orin Nano**, το «Chloros

» ελέγχει τη μέγιστη συχνότητα της GPU και την περιορίζει στα **510 MHz** (510000000) αν αυτή τη στιγμή είναι υψηλότερη:

* Αν τοCLI

μπορεί να γράψει στον κόμβο sysfs της συχνότητας της GPU, το όριο **εφαρμόζεται αυτόματα** και εμφανίζεται ένα μήνυμα επιβεβαίωσης.
* Εάν όχι (απαιτείται δικαίωμα root), τοCLI

εμφανίζει την ακριβή εντολή `sudo` για να εφαρμόσετε το όριο χειροκίνητα, περιμένει για λίγο ώστε να προλάβετε να τη διαβάσετε και στη συνέχεια συνεχίζει — η επεξεργασία συνεχίζεται, αλλά ενδέχεται να εμφανιστούν προειδοποιήσεις υπερβολικού ρεύματος.

Για να εφαρμόσετε εσείς το όριο πριν από την επεξεργασία:

```bash
echo 510000000 | sudo tee /sys/devices/platform/bus@0/17000000.gpu/devfreq/17000000.gpu/max_freq
```

Τα μοντέλα υψηλότερης ισχύος (Orin NX 25W, AGX Orin 60W) λειτουργούν στην πλήρη ταχύτητα της GPU· δεν εφαρμόζεται όριο. Το Standard debayer δεν ενεργοποιεί ποτέ το όριο σε κανένα μοντέλο.

{% hint style="info" %}
**Το Texture Aware στο Jetson εκτελεί πάντα μία εικόνα κάθε φορά.** Κάθε worker θα χρειαζόταν το δικό του πλαίσιο CUDA (~1 GB) καθώς και το δικό του αντίγραφο του μοντέλου αποθορυβοποίησης, κάτι που η ενοποιημένη μνήμη δεν μπορεί να υποστηρίξει — επομένως, στο Jetson η διαδρομή του Texture Aware περιορίζεται σε έναν μόνο worker με σειριοποιημένη πρόσβαση στην GPU. Αναμένεται το Texture Aware να είναι αισθητά πιο αργό από το Standard σε οποιοδήποτε Jetson.
{% endhint %}

## Διαχείριση θερμοκρασίας

Οι συσκευές Jetson έχουν περιορισμένο θερμικό περιθώριο, ειδικά σε κλειστές εγκαταστάσεις ή σε εφαρμογές με χρήση αεροσκαφών. ΤοChloros

παρακολουθεί τη θερμοκρασία του SoC και περιορίζει αυτόματα το μέγεθος των παρτίδων:

| Θερμοκρασία         | Ενέργεια                                            |
| ------------------- | ------------------------------------------------- |
| **&lt; 70°C**          | Κανονική λειτουργία — πλήρης ταχύτητα επεξεργασίας          |
| **70°C** (Προειδοποίηση) | Το μέγεθος των παρτίδων μειώνεται προοδευτικά (100% → 50% μεταξύ 70°C και 80°C) |
| **80°C** (Κρίσιμη) | Αυστηρός περιορισμός (50% → 0% μεταξύ 80°C και 90°C) |
| **90°C** (Τερματισμός λειτουργίας) | Πλήρης διακοπή της επεξεργασίας της GPU — απαιτείται ψύξη |

{% hint style="warning" %}
**Εξασφαλίστε επαρκή αερισμό και απαγωγή θερμότητας** για συνεχή επεξεργασία, ειδικά σε κλειστά περιβλήματα πεδίου ή αερομεταφερόμενα συστήματα. Ο θερμικός περιορισμός θα μειώσει την απόδοση επεξεργασίας για την προστασία του υλικού.
{% endhint %}

## Διαχείριση μνήμης

Οι συσκευές Jetson χρησιμοποιούν **ενοποιημένη μνήμη** — η GPU και η CPU μοιράζονται την ίδια φυσική μνήμη RAM. Η αναφερόμενη VRAM (π.χ. ~15,3 GB σε ένα Orin NX 16 GB) δεν είναι αποκλειστική μνήμη GPU· είναι η ίδια μνήμη RAM που χρησιμοποιούν το λειτουργικό σύστημα και κάθε άλλη διεργασία.

### Προειδοποίηση και συστάσεις σχετικά με την ανταλλαγή

Πριν από την επεξεργασία στο Jetson, τοCLI

μετρά τις εικόνες RAW στον φάκελο εισόδου σας (`.tif`, `.tiff`, `.raw`, `.dng` — οι προεπισκοπήσεις JPG δεν υπολογίζονται), εκτιμά τη μέγιστη μνήμη που απαιτεί η εκτέλεση και **προειδοποιεί πριν από την έναρξη** εάν η μνήμη RAM + η μνήμη swap είναι πιθανό να μην επαρκούν. Η προειδοποίηση έχει τίτλο `LOW MEMORY WARNING - Jetson Detected`, εμφανίζει τον αριθμό των εικόνων σας, τη μνήμη RAM, τον τρέχοντα χώρο swap και την εκτιμώμενη μέγιστη χρήση, και στη συνέχεια παρέχει τις ακριβείς εντολές `fallocate` / `chmod` / `mkswap` / `swapon` εντολές προσαρμοσμένες στο μέγεθος του έργου σας (ποτέ μικρότερες από 8 GB). Παύει για λίγα δευτερόλεπτα ώστε το μήνυμα να μην χαθεί κατά την κύλιση προς τα πίσω, και στη συνέχεια η επεξεργασία συνεχίζεται.**Εκτιμήσεις μνήμης που χρησιμοποιούνται από την προειδοποίηση:**

| Λειτουργία Debayer | Βάση | Ανά εικόνα |
| --- | --- | --- |
| Τυπική | ~1,5 GB | ~10 MB |
| Με αναγνώριση υφής | ~2,5 GB (μοντέλο + χρόνος εκτέλεσης τουPython

) | ~15 MB |

Η προειδοποίηση ενεργοποιείται όταν η εκτιμώμενη μέγιστη τιμή υπερβαίνει τη μνήμη RAM + τη μνήμη ανταλλαγής (swap) μείον ένα περιθώριο ασφαλείας 1 GB, και υπολογίζει μόνο τη μνήμη ανταλλαγής που **υποστηρίζεται από αρχεία** — μια ρύθμιση που βασίζεται αποκλειστικά σε zram θα εξακολουθεί να επισημαίνεται.

Για να προσθέσετε swap χειροκίνητα (παράδειγμα: 8 GB):

```bash
# Check current memory and swap
free -h

# Create a swap file
sudo fallocate -l 8G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile

# Make persistent across reboots
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
```

### Χειρισμός OOM (Out of Memory)

Κατά τη διάρκεια της επεξεργασίας, τοChloros

παρακολουθεί τη μνήμη της GPU και μειώνει ομαλά την απόδοση αντί να διακοπεί η λειτουργία:

1. Όταν η χρήση της μνήμης της GPU υπερβαίνει το **85%**, τα μεγέθη των παρτίδων μειώνονται προληπτικά
2. Εάν εξακολουθεί να εμφανίζεται συμβάν εξάντλησης μνήμης, το μέγεθος της παρτίδας **μειώνεται στο μισό** και μειώνεται ξανά στο μισό σε κάθε διαδοχικό OOM· κάθε επόμενη επιτυχημένη παρτίδα αναστρέφει αυτή την ποινή κατά ένα βήμα
3. Υπό συνεχή πίεση, ο αγωγός επιστρέφει από το `fused_gpu` στη διαδρομή `tiled_gpu`, η οποία είναι αποδοτικότερη ως προς τη μνήμη, και, ως έσχατη λύση, στην επεξεργασία από την CPU

### Backend συνεχούς λειτουργίας για συγχρονισμό χρόνου LATTICE / DAQ-E

Εάν το Jetson σας ελέγχει κάμερες LATTICE ή αισθητήρες φωτός DAQ-E χωρίς οθόνη, ενεργοποιήστε την υπηρεσία systemd του backend ώστε ο grandmaster PTP να λειτουργεί συνεχώς (η μονάδα είναι εγκατεστημένη αλλά δεν είναι ενεργοποιημένη από προεπιλογή):

```bash

chloros-cli time-sync status
```

Δείτε την [Εγκατάσταση τουLinux

](linux-installation.md#always-on-ptp-for-headless-hosts) για λεπτομέρειες, συμπεριλαμβανομένου του τρόπου με τον οποίο το πακέτο καθιστά τις θύρες PTP 319/320 δεσμεύσιμες χωρίς δικαιώματα root.

### Αυτοματοποιημένη επεξεργασία με το systemd

Δημιουργήστε μια υπηρεσία systemd για αυτοματοποιημένη επεξεργασία:

```ini
# /etc/systemd/system/chloros-process.service
[Unit]
Description=Chloros Automated Processing
After=network.target

[Service]
Type=oneshot
User=chloros
ExecStart=/usr/bin/chloros-cli process /data/incoming --output /data/processed
StandardOutput=append:/var/log/chloros-process.log
StandardError=append:/var/log/chloros-process.log

[Install]
WantedBy=multi-user.target
```

Το `chloros-cli process` τερματίζεται με μη μηδενικό αποτέλεσμα όταν μια εκτέλεση που ζήτησε προϊόντα δεν εγγράφει εικόνες, οπότε η κατάσταση αποτυχίας του systemd είναι σημαντική για την παρακολούθηση.

Συνδυάστε την με έναν χρονοδιακόπτη του systemd για προγραμματισμένη επεξεργασία:

```ini
# /etc/systemd/system/chloros-process.timer
[Unit]
Description=Run Chloros Processing Every Hour

[Timer]
OnCalendar=hourly
Persistent=true

[Install]
WantedBy=timers.target
```

```bash
sudo systemctl enable chloros-process.timer
sudo systemctl start chloros-process.timer
```

## Παραδείγματα ροών εργασίας

### Βασική επεξεργασία στο Jetson

```bash
#!/bin/bash
# Process a drone flight dataset on Jetson
chloros-cli process /data/flights/flight_042 \
    --output /data/processed/flight_042 \
    --format "TIFF (32-bit, Percent)" \
    --indices NDVI NDRE GNDVI
```

###Python

SDK

στο Jetson

```python
from chloros_sdk import ChlorosLocal

with ChlorosLocal() as chloros:
    chloros.create_project("field_survey_042")
    chloros.import_images("/data/flights/flight_042")
    chloros.configure(
        indices=["NDVI", "NDRE", "GNDVI"],
        export_format="TIFF (32-bit, Percent)",
        reflectance_calibration=True
    )
    chloros.process(mode="parallel")

print("Processing complete!")
```

### Μαζική επεξεργασία πολλαπλών πτήσεων

```bash
#!/bin/bash
# Process all flight datasets in a directory
for flight in /data/flights/*/; do
    name=$(basename "$flight")
    echo "Processing $name..."
    chloros-cli process "$flight" \
        --output "/data/processed/$name" \
        --format "TIFF (32-bit, Percent)" \
        --indices NDVI NDRE
    echo "Completed $name"
done
```

## Συνιστώμενα συστήματα Jetson για χρήση στο πεδίο

Για εφαρμογές στο πεδίο και σε αεροσκάφη, εξετάστε τις ακόλουθες επιλογές πλακέτας φορέα Jetson Orin NX 16GB:

* **Αερομεταφερόμενα/drone**: Συστήματα με βαθμολογία αντοχής σε κραδασμούς (MIL-STD), ελαφρύ βάρος (κάτω από 300 g), παθητική ψύξη
* **Ανθεκτικά για χρήση στο πεδίο**: Αδιάβροχα περιβλήματα IP67/IP69K με δυνατότητα σύνδεσης κάμερας GigE μέσω PoE
* **Ελάχιστες απαιτήσεις/οικονομική λύση**: Σετ ανάπτυξης με πρόσθετα περιβλήματα

Επικοινωνήστε με την [ΥποστήριξηMAPIR

](https://www.mapir.camera/community/contact) για συγκεκριμένες προτάσεις υλικού ανάλογα με το σενάριο χρήσης σας.
