# Συστοιχίες πολλαπλών καμερών

Μια **συστοιχία**LATTICE αποτελείται από δύο ή περισσότερες κάμερες LATTICE συνδεδεμένες ως μία συγχρονισμένη μονάδα. Μία κάμερα λειτουργεί ως**κύρια**: εκπέμπει έναν παλμό ενεργοποίησης GPIO μέσω υλικού σε μια κοινή γραμμή συγχρονισμού (προεπιλογή**Line2**), έτσι ώστε κάθε κάμερα της συστοιχίας να καταγράφει την ίδια χρονική στιγμή. Το Chloros προσθέτει χρονικό συγχρονισμό PTP, ζωντανή προεπισκόπηση (πλακίδια ανά κάμερα ή ένα ενιαίο ευθυγραμμισμένο σύνθετο πολυζωνικό εικόνα) και συγχρονισμένη λήψη — κάθε κύκλος λήψης παράγει μία**ομάδα καρέ** στην οποία όλες οι κάμερες μοιράζονται την ίδια χρονική σήμανση και τον ίδιο αναγνωριστικό καρέ (που αναγράφεται ως `fid:N` στην έξοδο λήψης).

Οι συστοιχίες είναι ο τρόπος με τον οποίο οι μονοχρωματικές (M3M) κάμερες παράγουν δείκτες βλάστησης — μία κάμερα συνεισφέρει μία ζώνη, και η συστοιχία τις ευθυγραμμίζει σε μια πολυζωνική στοίβα. Βλ. [Μονοχρωματικές κάμερες &amp; δείκτες βλάστησης](mono-indices.md).

Υπάρχουν τρεις ισοδύναμοι τρόποι σύνδεσης ενός πίνακα, και όλοι εκτελούν την ίδια ροή «smart-prep»:

| Επιφάνεια | Σημείο εισόδου |
| --- | --- |
| GUI | Καρτέλα «Κάμερες» → **Σύνδεση πίνακα** (μπλε κουμπί) |
| CLI | `chloros-cli lattice array-connect --serials SN1,SN2,…` (ο πρώτος σειριακός αριθμός = κύριος) |
| Python SDK | `connect_array(serials=[…])` → `ArraySession` (ο πρώτος σειριακός αριθμός = κύριος) |

Το Smart-prep εκτελεί, με τη σειρά: έλεγχο δυνατοτήτων δικτύου (ICMP DF ping + έλεγχος GVSP), επιλογή επιπέδου συγχρονισμού, αυτόματη συρρίκνωση του μεγέθους πλαισίου για προσαρμογή στο καλώδιο, ενεργοποίηση PTP, αυτόματη επιλογή μορφής pixel ανά κάμερα, αυτόματη ρύθμιση έκθεσης με βάση την αποθηκευμένη κατάσταση κάθε κάμερας και διαμόρφωση ενεργοποίησης GPIO στη Γραμμή 2.

{% hint style="info" %}
Οι κάμερες πρέπει να είναι προσβάσιμες μέσω της σύνδεσης πριν λειτουργήσει οτιδήποτε από τα παραπάνω — δείτε [Σύνδεση καμερών](connecting.md) για την ανίχνευση, τη διευθυνσιοδότηση και τη λήψη βαθμονόμησης κατά την πρώτη σύνδεση. Για συστοιχίες πολλαπλών καμερών, οι ρυθμίσεις του δακτυλίου λήψης της κάρτας δικτύου του κεντρικού υπολογιστή (Host NIC) είναι εξίσου σημαντικές με την ταχύτητα της σύνδεσης· ο πλήρης πίνακας συμπτωμάτων→διόρθωσης βρίσκεται στο [CLI Αναφορά § Ρύθμιση &amp; Βελτιστοποίηση κάρτας δικτύου κεντρικού υπολογιστή](../reference/cli-reference.md#host-nic-setup--tuning-lattice-arrays).
{% endhint %}

## Το παράθυρο διαλόγου «Σύνδεση συστοιχίας»

Η καρτέλα «Κάμερες» → **Σύνδεση συστοιχίας**ανοίγει έναν οδηγό τριών βημάτων:**Επιλογή → Λειτουργία οθόνης → Ρυθμίσεις**.

### Βήμα 1 — Επιλογή κύριας και δευτερευουσών

<!-- SCREENSHOT-NEEDED: Array Connect dialog, Select scene, with 3-4 LATTICE cameras discovered. Table showing Camera / Serial / IP / Master radio / Slave checkbox columns, with the green "GPIO master detected — selections pre-populated" probe banner visible above the table. -->

καμερών Το παράθυρο διαλόγου σαρώνει το δίκτυο μόλις ανοίξει («Σάρωση δικτύου...»), και στη συνέχεια ελέγχει την καλωδίωση ενεργοποίησης GPIO («Έλεγχος καλωδίωσης GPIO...»). Χρειάζεστε τουλάχιστον **2 κάμερες** για να δημιουργήσετε μια συστοιχία.

Ο έλεγχος της καλωδίωσης συμπληρώνει αυτόματα την επιλογή ρόλου, όταν είναι δυνατό, και εμφανίζει ένα από τα τρία παρακάτω μηνύματα:

| Μήνυμα | Σημασία |
| --- | --- |
| «Εντοπίστηκε κύρια συσκευή GPIO — οι επιλογές έχουν συμπληρωθεί αυτόματα» (πράσινο) | Ο έλεγχος εντόπισε την τοπολογία ενεργοποίησης· τα πλαίσια επιλογής για την κύρια και τις δευτερεύουσες συσκευές έχουν ήδη συμπληρωθεί. |
| «Δεν εντοπίστηκε κύρια συσκευή — ελέγξτε το καλώδιο GPIO» (πορτοκαλί) | Καμία κάμερα δεν ανίχνευσε παλμό ενεργοποίησης· ελέγξτε την καλωδίωση συγχρονισμού. Μπορείτε ακόμα να επιλέξετε τους ρόλους χειροκίνητα. |
| «Χωρίς καλώδιο συγχρονισμού: {serials}» (πορτοκαλί) | Οι αναφερόμενες κάμερες δεν έχουν συνδεδεμένο καλώδιο συγχρονισμού. |

Ο πίνακας καμερών περιλαμβάνει τις στήλες **Κάμερα / Σειριακή θύρα / IP / Κύρια (ραδιόφωνο) / Δευτερεύουσα (πλαίσιο επιλογής)**:

* Επιλέξτε ακριβώς **μία κύρια**και**μία ή περισσότερες δευτερεύουσες**. Αν κάνετε ξανά κλικ στο ραδιόφωνο της τρέχουσας κύριας κάμερας, η επιλογή θα διαγραφεί.
* Μια κάμερα με την ένδειξη **«Χωρίς καλώδιο συγχρονισμού»** δεν μπορεί ποτέ να επιλεγεί ως δευτερεύουσα — μια δευτερεύουσα κάμερα χωρίς καλωδίωση ενεργοποίησης θα περίμενε για πάντα στη γραμμή συγχρονισμού και θα παρέχει ένα νεκρό σήμα. Συνδέστε την κάμερα αυτή ως αυτόνομη κάμερα αντ&#x27; αυτού.
* Οι κάμερες που είναι ήδη συνδεδεμένες ως αυτόνομες *δεν* απενεργοποιούνται: η σύνδεση σε συστοιχία απελευθερώνει τη συνεδρία αυτόνομης λειτουργίας και ανοίγει εκ νέου την κάμερα εντός της συστοιχίας.

**Επόμενο: Λειτουργία οθόνης →**ενεργοποιείται μόλις επιλεγούν ένας κύριος και τουλάχιστον ένας δευτερεύων. Το**Επανέλεγχος** εκτελεί εκ νέου την ανίχνευση και τον έλεγχο καλωδίωσης.

{% hint style="warning" %}
Το **Cancel** είναι απενεργοποιημένο ενώ βρίσκεται σε εξέλιξη σάρωση ή έλεγχος καλωδίωσης — η ακύρωση εν μέσω ελέγχου μπορεί να προκαλέσει σφάλμα στην κάμερα SDK με το υλικολογισμικό κάμερας LATTICE. Περιμένετε μέχρι να ολοκληρωθεί ο δείκτης προόδου.
{% endhint %}

### Βήμα 3 — Ρυθμίσεις συστοιχίας και το προβλεπόμενο αποτέλεσμα

<!-- SCREENSHOT-NEEDED: Array Connect dialog, Settings scene, healthy state: left column with ROI / Binning / Pin resolution / Trigger Rate controls, right "Projected Outcome" column showing green "Simultaneous capture" tier, an fps range, the NIC line, the "Sim-emit burst" line, and the "Wire budget" line with a checkmark. -->

Κατά την είσοδο σε αυτή τη σκηνή, το Chloros ζητά από το backend μια **σύσταση**και εφαρμόζει αυτόματα έναν συνδυασμό ROI + binning που ταιριάζει στον δακτύλιο λήψης του NIC σας (προτιμά το binning αντί της περικοπής ROI, επειδή το binning διατηρεί το πλήρες οπτικό πεδίο). Κάθε αλλαγή που κάνετε εκτελεί εκ νέου την ανάλυση σε πραγματικό χρόνο και ενημερώνει το δεξιό πλαίσιο**Προβλεπόμενο αποτέλεσμα**.

Αριστερή στήλη — ρυθμίσεις:

| Έλεγχος | Επιλογές | Προεπιλογή | Σημειώσεις |
| --- | --- | --- | --- |
| **ROI (Οπτικό πεδίο)** | Πλήρες (2048×1536) / Μισό (1024×768) / Τέταρτο (512×384) | Πλήρες | Περικοπή αισθητήρα: Περικοπή στο μισό/τέταρτο σε μικρότερη περιοχή με εγγενή απόσταση μεταξύ εικονοστοιχείων. |
| **Binning** | 1× / 2× (άθροισμα 2×2) / 4× (άθροισμα 4×4) | 1× | Συγκέντρωση εικονοστοιχείων στο υλικό: 2×2 = πλήρες FoV με το ένα τέταρτο του κόστους μεταφοράς δεδομένων· 4×4 = πλήρες FoV με το 1/16. Αποκρύπτεται αν οι κάμερες δεν υποστηρίζουν συγκέντρωση εικονοστοιχείων. |
| **Εικόνα από την πλευρά του καλωδίου**(ανάγνωση) | — | — | Το πλάτος × ύψος μετά το**binning** που αποστέλλεται πραγματικά μέσω του καλωδίου, στρογγυλοποιημένο σε πολλαπλάσια του 16 (ελάχιστο 64). |
| **Ανάλυση ακίδων**| πλαίσιο επιλογής | απενεργοποιημένο | Το Chloros αυξάνει συνήθως αυτόματα το binning κατά τη σύνδεση όταν ο προβλεπόμενος ρυθμός πέφτει κάτω από**1,5 fps**. Η δέσμευση διατηρεί το επιλεγμένο μέγεθος καρέ και αποδέχεται τον χαμηλότερο ρυθμό — και μετατρέπει μια διαμόρφωση με υπερβολική ζήτηση σε απόρριψη σύνδεσης αντί για αυτόματη μείωση. |
| **Ρυθμός ενεργοποίησης** | 0,5–60 fps, βήμα 0,1 | κενό = αυτόματο | Ο ρυθμός ενεργοποίησης του κύριου συστήματος. Αφήστε το κενό για να το υπολογίσει το Chloros. |
| **Προϋπολογισμός καλωδίου**| 20–2000 MB/s, βήμα 10 | κενό = αυτόματο | Πόσο μπορεί πραγματικά να απορροφήσει ο κεντρικός υπολογιστής, σε MB/s —**ο μοναδικός αριθμός από τον οποίο εξαρτάται ολόκληρη η κατανομή της συστοιχίας.** Ανιχνεύεται αυτόματα από τον προσαρμογέα δικτύου. Μειώστε τον αν η συστοιχία αναφέρει κατεστραμμένα πλαίσια: η ανιχνευόμενη τιμή υπερεκτιμά τους προσαρμογείς USB και τους κοινόχρηστους διακόπτες. Η αλλαγή του επαναλαμβάνει την προβολή σε πραγματικό χρόνο. |

Δεξιά στήλη — **Προβλεπόμενο αποτέλεσμα**:

* **Επίπεδο συγχρονισμού** — «Ταυτόχρονη λήψη» (πράσινο), «Ταυτόχρονη λήψη (FTD-κλιμακωτή εκπομπή)» (πράσινο), «Κλιμακωτή λήψη (απόκλιση 100 ms)» (πορτοκαλί) ή «Πάρα πολύ μεγάλη διαμόρφωση» (κόκκινο).
* ****Προβολή fps** — εμφανίζεται ως εύρος («αμυδρό → φωτεινό»), επειδή ο ρυθμός ενός συγχρονισμένου πλέγματος περιορίζεται από την έκθεση της πιο αργής κάμερας.
* **Γραμμή NIC** — ταχύτητα σύνδεσης και σταθερή απόδοση («NIC {mbps} Mbps · σταθερή {N} MB/s»).
* **Έλεγχος ριπής ταυτόχρονης εκπομπής** — μπορεί ο δακτύλιος λήψης της κάρτας δικτύου του κεντρικού υπολογιστή να απορροφήσει μία ταυτόχρονη ριπή από όλες τις κάμερες («Ριπή ταυτόχρονης εκπομπής: X MB · Χρησιμοποιήσιμος δακτύλιος NIC: Y MB ✓/✗»).
* **Έλεγχος προϋπολογισμού καλωδίου** — συνολική ζήτηση σε σταθερή κατάσταση έναντι του ανώτατου ορίου καλωδίου χωρίς συγκρούσεις («Προϋπολογισμός καλωδίου: {ζήτηση} MB/s που απαιτείται από {n} κάμερες · ανώτατο όριο {ceiling} MB/s ✓/✗ υπερ-εγγραφή»).
* **«Μέγιστος αριθμός καμερών σε αυτό το καλώδιο: {n} — καθορίζεται από το κατώτατο όριο εύρους ζώνης ανά κάμερα, οπότε η ομαδοποίηση δεν το αυξάνει.»** — εμφανίζεται όταν πλησιάζετε (ή πάνω από) το ανώτατο όριο αριθμού καμερών.
* **«ΘΑ ΧΑΝΟΝΤΑΙ ΚΑΔΡΑ με αυτές τις ρυθμίσεις.»**— κόκκινη προειδοποίηση με τον λόγο του backend, καθώς και λίστα εμποδίων και μπλε**προτάσεις διόρθωσης** («Για να χωρέσει αυτή η συστοιχία στο δίκτυο» / «Για να ξεκλειδωθεί η ταυτόχρονη καταγραφή»).

Το **«Εφαρμογή &amp; Σύνδεση»** παραμένει απενεργοποιημένο έως ότου υπάρξει πρόβλεψη, και η ετικέτα του σας εξηγεί γιατί απορρίπτεται:

| Ετικέτα κουμπιού | Σημασία | Τι βοηθά πραγματικά |
| --- | --- | --- |
| «Ανάλυση...» | Η ανάλυση βρίσκεται ακόμη σε εξέλιξη. | Περιμένετε. |
| **«Πάρα πολλές κάμερες για αυτό το δίκτυο»**| Η συστοιχία υπερφορτώνει το καλώδιο (αποτυχία ελέγχου συνολικής χωρητικότητας). | Λιγότερες κάμερες, jumbo frames από άκρο σε άκρο ή ταχύτερη κάρτα δικτύου (NIC).**Μια μικρότερη περιοχή ενδιαφέροντος (ROI) ΔΕΝ θα βοηθήσει** — δείτε παρακάτω. |
| **«Μειώστε το ROI για ενεργοποίηση»** | Τα πλαίσια θα χάνονται με αυτές τις ρυθμίσεις (αποτυχία ελέγχου ριπής/δακτυλίου). | Μειώστε το ROI, αυξήστε το binning ή διορθώστε το δακτύλιο λήψης της κάρτας δικτύου. |

Κατά τη σύνδεση, ενδέχεται να εμφανιστεί ένα πράσινο **παράθυρο λήψης βαθμονόμησης** με μια γραμμή προόδου ανά σειριακή θύρα: την πρώτη φορά που συνδέεται μια κάμερα σε έναν υπολογιστή, το Chloros αντλεί το πακέτο εργοστασιακής βαθμονόμησης ~3,8 MB από την κάμερα μέσω GigE (περίπου 70 δευτερόλεπτα ανά κάμερα). Οι κάμερες που έχουν αποθηκευτεί στην προσωρινή μνήμη δεν εμφανίζουν ποτέ αυτό το πλαίσιο. Δείτε [Σύνδεση καμερών](connecting.md).

## Εύρος ζώνης: πόσες κάμερες χωράνε

Το πόσες κάμερες μπορεί να υποστηρίξει μια συστοιχία εξαρτάται από το καλώδιο και όχι από το Chloros, οπότε οι αριθμοί σχεδιασμού αναφέρονται στο εγχειρίδιο του υλικού: **[Σχεδιασμός εύρους ζώνης συστοιχίας](https://mapir.gitbook.io/lattice-camera/setup/array-bandwidth-planning)**.

Τι κάνει το Chloros με αυτά: το παράθυρο διαλόγου σύνδεσης εκτελεί έλεγχο δικτύου, προβάλλει τον εφικτό ρυθμό καρέ και επιλέγει ένα επίπεδο που ταιριάζει. Εάν η συστοιχία υπερφορτώσει το καλώδιο, αρνείται τη σύνδεση αντί να απορρίπτει πακέτα σιωπηλά — δείτε το πλαίσιο προβλεπόμενου αποτελέσματος που περιγράφεται παραπάνω.

## Όταν χάνονται πλαίσια

Μια κάμερα μπορεί να απουσιάζει από μια δημοσιευμένη ομάδα για δύο εντελώς διαφορετικούς λόγους,
και απαιτούν αντίθετες λύσεις. Το Chloros τα καταμετρά ξεχωριστά αντί να αναφέρει έναν
«ατελή» αριθμό που δεν προσδιορίζει κανέναν από τους δύο:

| Τι συνέβη | Τι σημαίνει | Πού να ψάξετε |
| --- | --- | --- |
| **Κατεστραμμένο**— το πλαίσιο έφτασε αλλά ήταν δομικά ελαττωματικό | Απώλεια πακέτων GVSP στη διαδρομή του δικτύου | Το**wire budget**, ο δακτύλιος λήψης της κάρτας δικτύου, τα jumbo frames, ο διακόπτης |
| **Δεν έφτασε ποτέ**— δεν έφτασε κανένα πλαίσιο | Η κάμερα δεν ενεργοποιήθηκε, ή δεν εξήλθε τίποτα από αυτήν | Το**καλώδιο συγχρονισμού M8**, η γραμμή συγχρονισμού, αν όλα τα μέλη είναι ενεργοποιημένα |

Η κατανομή επαναξιολογείται κάθε 10 δευτερόλεπτα κατά τη ροή δεδομένων της συστοιχίας. Πάνω από 5 % καταγράφεται
με αναφορά και των δύο αριθμών, και κάθε κατεστραμμένος buffer αναφέρεται την πρώτη φορά που
συμβαίνει ανά κάμερα, και στη συνέχεια συγκεντρώνεται μία φορά το λεπτό, ώστε μια μακρά συνεδρία να παραμένει αναγνώσιμη.

**Τα κατεστραμμένα πλαίσια με μηδενικό αριθμό «δεν έφτασε ποτέ» σημαίνουν ότι η ενεργοποίηση και ο συγχρονισμός καλωδίου είναι τέλειοι**και κάθε χαμένο πλαίσιο βρίσκεται στη διαδρομή του δικτύου. Η λύση είναι να μειώσετε το**Wire Budget** και
να επανασυνδεθείτε.

{% hint style="warning" %}
**Η μείωση του ρυθμού ενεργοποίησης δεν βοηθά με τα κατεστραμμένα καρέ.** Ο ρυθμός αποστολής πακέτων
της κάμερας καθορίζεται μία φορά, κατά τη σύνδεση. Η μείωση του ρυθμού ενεργοποίησης αλλάζει τη συχνότητα με την οποία συμβαίνει μια ριπή
, όχι το πόσο γρήγορα η ίδια η ριπή μεταφέρεται στο καλώδιο. Σε μια συσκευή με 4 κάμερες που μετρήθηκε, μια
η μείωση του ρυθμού ενεργοποίησης κατά 5 φορές δεν άλλαξε τίποτα, ενώ η μείωση του **Wire Budget** από 240 σε
200 MB/s μείωσε το ποσοστό κατεστραμμένων πλαισίων της ίδιας διάταξης από 10,4 % στο μηδέν.
{% endhint %}

Ένα σύστημα που βρίσκεται σε λειτουργία δεν μπορεί να επαναπρογραμματιστεί — αποσυνδέστε και επανασυνδέστε, ώστε ο μηχανισμός επιλογής χρόνου σύνδεσης
να μπορεί να λειτουργήσει με βάση το νέο όριο.

### Οι προσαρμογείς δικτύου USB έχουν ανώτατο όριο τα 200 MB/s

Ένας προσαρμογέας Ethernet USB δηλώνει τον ρυθμό σύνδεσης *Ethernet* του, αλλά αυτό που μπορεί πραγματικά
να διατηρήσει περιορίζεται από τον δίαυλο USB και τον οδηγό του. Ένα dongle USB 10GbE θεωρούνταν παλαιότερα
ότι είχε διακίνηση περίπου 1000 MB/s — ένας αριθμός που δεν είχε μετρηθεί ποτέ — και η ρύθμιση
τέσσερις κάμερες με βάση αυτό το φανταστικό περιθώριο, προκαλούσε αλλοίωση στο 6–18 % των καρέ, ενώ η συστοιχία
εξακολουθούσε να αναφέρει έναν ικανοποιητικό στόχο ρυθμού καρέ. Οι προσαρμογείς που συνδέονται μέσω USB έχουν πλέον ανώτατο όριο στα
**200 MB/s**. Το όριο αυτό είναι απόλυτο και όχι ποσοστιαίο, επειδή το περιοριστικό στοιχείο είναι ο
δίαυλος: ένας προσαρμογέας USB 1 GbE αποδίδει περίπου 80 MB/s και δεν επηρεάζεται.

Εάν ο κεντρικός υπολογιστής σας είναι πραγματικά ταχύτερος από το όριο, αυξήστε το **Wire Budget** για να το δηλώσετε.

## Συγχρονισμός χρόνου PTP

Ο *συγχρονισμός* των καρέ προέρχεται από το ερέθισμα του υλικού· το **PTP** (IEEE 1588 PTPv2) παρέχει συγκρίσιμες *χρονοσημάνσεις* σε όλες τις συσκευές. Είναι ενεργοποιημένο από προεπιλογή κατά τη σύνδεση του συστοιχείου:

* Το **backend του κεντρικού υπολογιστή Chloros εκτελεί τον grandmaster PTP**. Οι κάμερες LATTICE και οι αισθητήρες φωτός DAQ-E λειτουργούν ως υποτελείς σε αυτόν στον τομέα 0, οπότε οι χρονικές σφραγίδες των εικόνων και τα φάσματα DAQ συγχρονίζονται σε ένα ρολόι (~1 ms).
* Το `--no-ptp` (CLI) το απενεργοποιεί για εργασίες σε πάγκο — οι χρονικές σημάνσεις μεταξύ των καμερών **δεν** είναι τότε συγκρίσιμες.
* Ελέγξτε την κατάσταση του συγχρονισμού με το CLI:

```bash
chloros-cli time-sync status     # grandmaster state, clock identity
chloros-cli time-sync peers      # slaves seen (cameras + DAQ-E sensors)
chloros-cli time-sync cameras    # per-camera PtpStatus / PtpOffsetFromMaster / PtpMeanPathDelay
```

Η καρτέλα «Κάμερες» (Cameras) δεν διαθέτει ένδειξη PTP· εκεί εμφανίζονται οι πληροφορίες συγχρονισμού ανά κάμερα: το **Ρόλο**(Master/Slave) που είναι μόνο για ανάγνωση, η**Γραμμή Συγχρονισμού** (Sync Line) και το επίπεδο δυνατοτήτων (Capabilities) της συστοιχίας. Η κατάσταση PTP του DAQ-E εμφανίζεται στις λεπτομέρειες αισθητήρων της καρτέλας «Αισθητήρες Φωτός» (Light Sensors).

## Η ζωντανή προβολή

<!-- SCREENSHOT-NEEDED: Cameras tab with a connected combined array: sidebar showing the ARRAY row (color badge, array name, "DAQ · on" pill) with indented member camera rows, and the main area showing the combined index composite tile with the LUT-colored NDVI render, top-left array name pill, and top-right fps readout. -->

της συστοιχίας Η κύρια περιοχή τροφοδοσίας προσφέρει δύο διατάξεις (εναλλαγή στην επάνω γραμμή): **προβολή πλέγματος**(κάθε πλακίδιο είναι ένα κελί· μετακίνηση για αναδιάταξη όταν το λουκέτο του πλέγματος είναι ξεκλείδωτο) και**προβολή λίστας**(οι συστοιχίες σε πλήρες πλάτος στην κορυφή, μία ενεργή κάμερα από κάτω). Το ρυθμιστικό**Zoom ροής** ρυθμίζει το μέγεθος των πλακιδίων· όταν το πλάτος του κελιού είναι κάτω από 200 px, οι επικαλύψεις ονόματος/fps κρύβονται αυτόματα.

Η **ξεχωριστή λειτουργία** εμφανίζει ένα πλακίδιο ανά κάμερα. Κάθε πλακίδιο εμφανίζει:

* το όνομα της κάμερας (πάνω αριστερά),
* μια **ένδειξη fps** (πάνω δεξιά) — αυτή είναι ο *πραγματικός ρυθμός λήψης* της κάμερας που αναφέρεται από το backend, όχι ο ρυθμός δειγματοληψίας της προεπισκόπησης (η ζωντανή προεπισκόπηση περιορίζεται στα 30 fps ανεξάρτητα από τον ρυθμό λήψης),
* μια κουκκίδα κατάστασης — πράσινη (μετάδοση) / πορτοκαλί (φόρτωση) / κόκκινη (σφάλμα),
* ένα **εικονίδιο αναμονής παλαιού καρέ** όταν δεν έχει φτάσει νέο καρέ για 2 δευτερόλεπτα — φυσιολογικό για ~5 δευτερόλεπτα μετά από οποιαδήποτε σύνδεση/αποσύνδεση, ενώ το backend εξισορροπεί εκ νέου τον προϋπολογισμό της σύνδεσης μεταξύ των καμερών.

Η **συνδυασμένη λειτουργία**εμφανίζει ένα ενιαίο σύνθετο πλακίδιο: το backend πραγματοποιεί αποσυνδυασμό, κλιμάκωση, ευθυγράμμιση, αποθορυβοποίηση, μετατροπή σε ακτινοβολία ανά ζώνη (συν ανακλαστικότητα DLS όταν έχει συνδεθεί αισθητήρας φωτός), αξιολογεί την έκφραση δείκτη της συστοιχίας, εφαρμόζει το LUT και μεταδίδει το αποτέλεσμα ως MJPEG. Μέχρι να αποδοθεί το πρώτο ευθυγραμμισμένο καρέ, το πλακίδιο εξηγεί την κατάστασή του: «Προετοιμασία συστοιχίας…», «Βαθμονόμηση ευθυγράμμισης…», «Αναμονή για το πρώτο καρέ…» ή — εάν εξαντληθεί ο χρόνος επαναληπτικών προσπαθειών αυτόματης ευθυγράμμισης (~30 δευτερόλεπτα) — «Απαιτείται ευθυγράμμιση» με ένα κουμπί**Βαθμονόμηση ευθυγράμμισης**.

Χρήσιμες πληροφορίες για τη συνδυασμένη λειτουργία:

* Το σύνθετο πλαίσιο συγχρονίζεται με το πλαίσιο της **κύριας**κάμερας. Η στόχευση AE-ROI και η σημειακή μέτρηση στο σύνθετο πλαίσιο είναι ακριβείς για την κύρια κάμερα και κατά προσέγγιση για τις δευτερεύουσες· χρησιμοποιήστε το**Split View** (ρυθμίσεις συστοιχίας → «Εμφάνιση καμερών-μελών») για πλακίδια ανά κάμερα με ακρίβεια εικονοστοιχείου χωρίς να ανοίξετε επιπλέον συνδέσεις καμερών.
* Η επιλογή **Εμφάνιση επιπέδων**(ρυθμίσεις συστοιχίας· προεπιλογή απενεργοποιημένη) σάς επιτρέπει να επιλέξετε ένα επίπεδο προσκηνίου και ένα επίπεδο φόντου — οποιαδήποτε κάμερα-μέλος ή το**Ευρετήριο**. Όταν το προσκήνιο είναι ρυθμισμένο σε «Ευρετήριο», τα εικονοστοιχεία εκτός των ορίων LUT Min/Max εμφανίζουν το επίπεδο φόντου.
* Η **ανάλυση απόδοσης** (προεπιλογή 720p) καθορίζει το ύψος της ζωντανής ροής *και* το μέγεθος εξαγωγής της αποθηκευμένης σύνθετης εικόνας. Οι εικόνες ανά κάμερα εξάγονται πάντα σε πλήρη ανάλυση.
* Η ευθυγράμμιση υπολογίζεται ανά συνεδρία και δεν αποθηκεύεται ποτέ — ανατρέξτε στην ενότητα ευθυγράμμισης του παραθύρου ρυθμίσεων συστοιχίας για τα υπολείμματα RMS και το κουμπί «Επαναβαθμονόμηση».

## Λήψη: παρακολούθηση έναντι ανάλυσης

Οι επιφάνειες λήψης της συστοιχίας χωρίζονται σαφώς σε **επιπέδου παρακολούθησης**(καταγράφουν ό,τι βλέπετε) και**επιπέδου ανάλυσης** (καταγράφουν ακατέργαστα δεδομένα, βαθμονομούνται αργότερα):

| Ροή εργασίας | Επίπεδο | Τι αποθηκεύει | GUI | CLI |
| --- | --- | --- | --- | --- |
| **Λήψη**(στατικές εικόνες) | Ανάλυση | Μία συγχρονισμένη ομάδα καρέ ανά πέρασμα· αρχεία ανά κάμερα σε κάθε επιλεγμένο επίπεδο εξαγωγής (ακατέργαστα/απο-debayered/ακτινοβολία/ανακλαστικότητα/προεπισκόπηση/δείκτης) + `.daq` sidecar | Κουμπί**Καταγραφή Όλων** + Ρυθμίσεις Καταγραφής | `lattice array-capture` |
| **Εγγραφή βίντεο δείκτη** | Παρακολούθηση | Το ζωντανό σύνθετο δείκτη όπως εμφανίζεται — 8-bit, ανάλυση προεπισκόπησης, ενσωματωμένο LUT· απαιτείται η ροή ζωντανής εικόνας να είναι ανοιχτή | ● Εγγραφή βίντεο δείκτη (συνδυασμένοι πίνακες) | `lattice array-record` |
| **Ακατέργαστη ροή → δημιουργία βίντεο**| Ανάλυση | Ακατέργαστα καρέ αισθητήρα σε πλήρη ρυθμό λήψης + κατάλογος + `.daq`, και στη συνέχεια ανακατασκευή εκτός σύνδεσης σε βίντεο βαθμονομημένης ακτινοβολίας / ανακλαστικότητας / δείκτη, χρονικά συγχρονισμένο με τις μετρήσεις DAQ | ⦿ Εγγραφή ακατέργαστης ροής →**Δημιουργία βίντεο** | `lattice array-burst` → `lattice array-build-video` |

Γενικός κανόνας: αν τα εικονοστοιχεία θα τροφοδοτήσουν *μετρήσεις*, χρησιμοποιήστε τη λειτουργία καταγραφής ή τη σειρά λήψεων (ποιότητα ανάλυσης)· αν απλώς θέλετε να *παρακολουθήσετε ή να επιδείξετε* αυτό που είδε η συστοιχία, καταγράψτε το βίντεο δείκτη (ποιότητα παρακολούθησης).

### Ρυθμίσεις καταγραφής (GUI)

<!-- SCREENSHOT-NEEDED: Capture Settings pane (gear next to Capture All) with a connected array: capture-mode buttons (Single/Continuous/Interval), the bulk export-type toggle row, the Fastest Capture toggle, and the per-array group card showing the Aligned checkbox and the "Record index video" / "Record raw burst" buttons. -->

Το εικονίδιο με το γρανάζι δίπλα στο **Capture All** ανοίγει το παράθυρο «Ρυθμίσεις καταγραφής» (απαιτείται ανοιχτό έργο — οι καταγραφές αποθηκεύονται σε αυτό):

* **Λειτουργία καταγραφής**:**Single**(μία διέλευση) /**Continuous**(διαδοχικά· περιορίζεται από έναν αριθμό καταγραφών, προεπιλογή 1, ή μια διάρκεια, προεπιλογή 10 s) /**Interval** (timelapse: N καταγραφές κάθε X διάστημα για Y συνολικά, προεπιλογή 1 κάθε 5 s για 1 λεπτό).
* **Τύποι εξαγωγής ανά κάμερα**: Raw, Debayered, Radiance, Reflectance, Preview, Index — όλα τα εφαρμόσιμα είναι ενεργοποιημένα από προεπιλογή. Τα Radiance/Reflectance είναι κρυμμένα για κάμερες τύπου RGB-filter·**το Reflectance εμφανίζεται μόνο όταν η κάμερα διαθέτει αισθητήρα φωτός DAQ** (δικό της ή κληρονομημένο από τη συστοιχία)· το Index απαιτεί διαμορφωμένη έκφραση ευρετηρίου.
* **Ευθυγραμμισμένο**(ανά συστοιχία, προεπιλογή**ενεργό**): παραμορφώνει τις εξαγωγές των μελών σύμφωνα με το προφίλ ευθυγράμμισης της συστοιχίας, ώστε οι εξαγωγές να είναι ευθυγραμμισμένες σε επίπεδο εικονοστοιχείου. Το Raw παραμένει πάντα χωρίς παραμόρφωση, αλλά μεταφέρει τη μετασχηματισμένη τιμή στα μεταδεδομένα.
* **Ταχύτερη λήψη** (εναλλαγή): μόνο ακατέργαστα δεδομένα + η εκχώρηση ανάγνωσης DAQ + το ελεύθερο σύνθετο συνδυασμένου δείκτη, παρακάμπτοντας τους μαθηματικούς υπολογισμούς βαθμονόμησης κατά τη στιγμή της λήψης για μέγιστο ρυθμό — ανακατασκευάστε την ακτινοβολία/αντανάκλαση/δείκτη αργότερα από το αποθηκευμένο `.daq`.
* Οι επιλογές διατηρούνται στο έργο. Οι κρυφές ή σε παύση κάμερες παραλείπονται.

Το αντίστοιχο CLI (ίδιο τελικό σημείο backend, ίδια σημασιολογία):

```bash
# One synced group, every applicable export level per camera (the default)
chloros-cli lattice array-capture -o output/

# Interval timelapse: one reflectance pass every 10 s for 5 minutes
chloros-cli lattice array-capture --interval 10 --duration 300 --processing reflectance -o timelapse/

# Fastest grab for a moving rig — raw + .daq now, calibrate later
chloros-cli lattice array-capture --fastest -o flightline/

# 30-second monitoring clip of the combined index view, plus a GIF
chloros-cli lattice array-record --duration 30 --fps 10 --gif -o monitoring/

# 5-second analysis-grade raw burst, then build the combined index video
chloros-cli lattice array-burst --duration 5 --build --products combined:index --fps 10 -o capture/
```

Η συμπίεση TIFF για τις λήψεις είναι `deflate` (χωρίς απώλειες, προεπιλογή) ή `none` — οι πλήρεις πίνακες σημαίας, η διάταξη του φακέλου καταγραφής και οι κανόνες επανεπεξεργασίας περιγράφονται στην [Αναφορά CLI](../reference/cli-reference.md#capture-modes-recorders--offline-reprocess).

## Σύνδεση ενός αισθητήρα φωτός DAQ

Οι προεπισκοπήσεις με διόρθωση ανακλαστικότητας και φωτισμού απαιτούν δεδομένα κατευθυνόμενου προς τα κάτω φωτός από έναν αισθητήρα DAQ (συνδεδεμένο στην καρτέλα **Αισθητήρες Φωτός**):

* Η **σειρά συστοιχίας**στην πλευρική γραμμή εμφανίζει ένα**κουμπί &quot;DAQ · on/off&quot;** — *ενεργοποιημένο* όταν έχει ρυθμιστεί ένας αισθητήρας φωτός σε επίπεδο συστοιχίας **ή** όταν οποιαδήποτε κάμερα της συστοιχίας διαθέτει δικό της αισθητήρα· το εργαλείο υποδείξεων του κουμπιού αναγράφει ακριβώς ποιος αισθητήρας τροφοδοτεί ποια κάμερα.
* Ορίστε τη ρύθμιση για ολόκληρο το πλέγμα στις ρυθμίσεις πλέγματος → **Αισθητήρας Περιβαλλοντικού Φωτός**→ αναπτυσσόμενο μενού**Αισθητήρας Φωτός**. Η επιλογή διατηρείται στο έργο, μεταφέρεται σε κάθε κάμερα του πλέγματος, ενώ οι μεμονωμένες κάμερες μπορούν να την παρακάμψουν χρησιμοποιώντας τον δικό τους αισθητήρα.
* Η γραμμή κατάστασης κάτω από αυτό αναφέρει την τρέχουσα κατάσταση: **Απενεργοποιημένος**→ «Αναμονή για το πρώτο φάσμα…» →**«Ενεργός — όλες οι κάμερες της συστοιχίας έχουν υποστεί διόρθωση φωτισμού»** → ή, αν δεν έχει ληφθεί νέο φάσμα τα τελευταία 3 δευτερόλεπτα, εμφανίζεται ειδοποίηση παλαιού δεδομένου — συνεχίζει να χρησιμοποιείται η τελευταία μέτρηση (οι μετρήσεις δεν λήγουν ποτέ στη διαδρομή καταγραφής).

Όταν έχει εκχωρηθεί αισθητήρας: ο τύπος εξαγωγής «Αντανακλαστικότητα» καθίσταται διαθέσιμος, οι ζωντανές προεπισκοπήσεις διορθώνονται ως προς τον φωτισμό, η προγνωστική αυτόματη έκθεση μπορεί να χρησιμοποιήσει το φάσμα και κάθε λήψη αντανακλαστικότητας εγγράφει την ένδειξη DAQ που χρησιμοποιήθηκε πράγματι ως **`.daq` sidecar** δίπλα στην εικόνα, ώστε η καταγραφή να μπορεί να υποβληθεί σε επανεπεξεργασία αργότερα.

## Επιλογές `array-connect` CLI

| Σημαία | Προεπιλογή | Περιγραφή |
| --- | --- | --- |
| `--serials SN1,SN2,…` | αυτόματη ανίχνευση όλων των καμερών LATTICE (απαιτούνται ≥2) | **Η πρώτη σειριακή θύρα είναι ο MASTER.** |
| `--line {Line0,Line2,Line3}` | `Line2` | Γραμμή συγχρονισμού GPIO. |
| `--target-fps F` | auto | Ρυθμός ενεργοποίησης Master. |
| `--binning {1,2,4}` | αυτόματο | Ταξινόμηση υλικού. |
| `--force-tier {sim-capture-sim-emit, sim-capture-ftd-stagger, slip-emit-and-capture}` | αυτόματο | Παράκαμψη από ειδικό του επιλογέα επιπέδου συγχρονισμού. |
| `--wire-ceiling-mbps MB_PER_S` | αυτόματη ανίχνευση | Προϋπολογισμός καλωδίου κεντρικού υπολογιστή σε MB/s — η μορφή CLI του πεδίου **Προϋπολογισμός καλωδίου**. Μειώστε τον εάν ο πίνακας αναφέρει κατεστραμμένα πλαίσια. Αποθηκεύεται μαζί με το έργο, οπότε μια μετέπειτα επανασύνδεση το επαναφέρει. |
| `--no-recommend` | απενεργοποιημένο | Παράλειψη του βήματος ανάλυσης δικτύου. |
| `--no-ptp` | απενεργοποιημένο | Απενεργοποίηση PTP (οι χρονικές σημάνσεις μεταξύ καμερών δεν είναι τότε συγκρίσιμες). |

Οι `lattice array-list`, `array-status` και `array-disconnect` διαχειρίζονται τη μόνιμη συνεδρία. Η πλήρης αναφορά υποεντολών, συμπεριλαμβανομένης της ευθυγράμμισης (`align-calibrate` / `align-apply`) και των εργαλείων δικτύου, βρίσκεται στο [CLI Αναφορά § chloros-cli lattice](../reference/cli-reference.md#chloros-cli-lattice). Τα αντίστοιχα των SDK (`connect_array`, `ArraySession`, `attach_array`, `analyze_array_network`) βρίσκονται στο [SDK Αναφορά](../reference/sdk-reference.md). Από το Python το «wire budget» είναι το `connect_array(..., wire_ceiling_mbps=120)`, και η διαίρεση μεταξύ «live corrupt» και «never-arrived» βρίσκεται στο [`/api/camera/array/<id>/capability`](../reference/sdk-reference.md#array-health--which-subsystem-is-losing-frames).
